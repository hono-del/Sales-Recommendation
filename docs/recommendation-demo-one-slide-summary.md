## このデモが示す本質（社内整理用）

**AIの性能より、「AIが参照する情報基盤」の質が提案の質を決める。**

弊社の強みである **情報の構造化** と **意味化** が、本PoCの中核にある。

| 弊社の強み | 本デモでの具体例 |
|-----------|----------------|
| **構造化** | 散在する顧客の声・サービス情報を Need / Load / Service / Capability として整理し、関係性を持たせる |
| **意味化** | 「静かに乗りたい」などの生の回答を、「静かな空間で移動したい」という**判断に使える概念**へ変換する |
| **情報基盤化** | 構造化・意味化した知識を LLM の外側に置き、AI が**参照**して根拠付き提案を行う |

> **サービス一覧そのものが「知識基盤」ではない。**  
> サービス・ニーズ・懸念・価値の**関係性として意味化された情報基盤**が、AI が参照する領域である。

## 1枚スライドの目的

デモを見た人に、単なるおすすめ表示ではなく、以下の価値を短時間で理解してもらう。

- 顧客の回答を**構造化・意味化**し、判断に使える概念（Need / Load / 価値観）に変換している
- AI はその情報を**覚えさせるのではなく**、**意味化情報基盤**を参照して根拠付き提案を行う
- 利用ログ・**利用フィードバック**を蓄積し、情報基盤と推薦精度が**継続的に育つ**

## 推奨スライド構成

### メインメッセージ

**散在する顧客情報を構造化・意味化した情報基盤を整備し、AI がそれを参照して根拠付きのサービス提案を行う。利用フィードバックを重ねるほど、基盤と提案が育つ。**

### 左: 入力（非構造 → 構造化）

**顧客の生の声**

- 質問への回答（言葉・選択肢）
- 価値観の傾向
- 困りごと・不安・期待

**弊社の処理: 構造化・意味化**

> Q回答 → 価値観プロファイル  
> 「静かに乗りたい」→ Need: 静かな空間で移動したい  
> 「選べない」→ Load: 情報過多による判断負荷

### 中央: 意味化情報基盤（★ 弊社のコア領域）

**意味化情報基盤**

LLM の外側に置く、**構造化・意味化された参照用の知識レイヤー**

- **Need** — 顧客が実現したいこと（意味化された欲求）
- **Load** — 避けたい負荷・不安（意味化された懸念）
- **Service** — 提案可能なサービス
- **Capability** — サービスが提供する価値
- **関係性** — どの Need / Load に、どの Service が効くか

表示例:

> Need = 静かな空間で移動したい  
> Load = 情報過多による判断負荷  
> Service = オーディオスマートチューニング  
> → AI はこの**関係性**を参照して提案する

### 右: 出力（根拠付き提案）

**根拠付きレコメンド**

- おすすめサービス
- 適合度スコア
- **参照した情報**（Need / Load / Service）
- 推薦理由
- 過去 FB によるスコア調整

表示例:

> 参照した情報: Need / Load / Service  
> このサービスは過去の FB によりスコア調整されました

### 下段: 継続改善

**基盤が育つ仕組み**

- ログ件数（利用実績）
- フィードバック件数
- 学習済みサービス件数
- 改善された推薦件数

一言で表すなら:

> **使うほど、意味化情報基盤と推薦精度が蓄積・更新される。**

## スライドに入れるべき3つの訴求点

### 1. ブラックボックスではない — 参照した情報が見える

なぜそのサービスが推薦されたかを、Need・Load・Service の**意味的な関係**として説明できる。

### 2. AI に「覚えさせない」— 意味化情報基盤を外側に持つ

LLM にサービス一覧や判断基準を覚えさせるのではなく、**弊社が構造化・意味化した情報基盤**を AI の外側に置き、提案のたびに参照させる。  
→ 知識の更新・監査・運用が可能。**ここが弊社の提供領域。**

### 3. 利用フィードバックで基盤が育つ

利用フィードバックを蓄積し、近い価値観プロファイルへの次回推薦へ反映。  
情報基盤と AI の提案が、利用とともに改善される。

## 口頭説明用メモ

- このデモの本質は「おすすめを出すこと」ではなく、**AI が参照する情報基盤**をどう設計するか、である。
- 弊社の強みは、散在する情報を **構造化** し、**意味化** して、AI が判断に使える形にすること。
- サービス名のリストではなく、**Need・Load・Service の関係性**として情報を持つ。これが AI が「参照する」対象。
- 推薦画面の「参照した知識」は、ブラックボックスではなく**どの意味情報を根拠にしたか**が見える設計。
- 利用ログ・利用フィードバックを蓄積することで、**情報基盤と推薦ロジックの両方**が育つ構造になっている。
