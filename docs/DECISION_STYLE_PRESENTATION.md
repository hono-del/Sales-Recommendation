# Decisionスタイル別 推薦結果表示方法

**作成日**: 2026-06-03  
**目的**: 各Decisionスタイルの特性に合わせた推薦結果の表示方法を定義

---

## 1. 基本方針

ユーザーの意思決定スタイル（6種類）に応じて、推薦結果の**情報密度**、**強調ポイント**、**提示順序**を最適化し、意思決定を支援する。

---

## 2. スタイル別表示設計

### 2.1 Maximizer（徹底比較型）

**特徴**: 多数比較・後悔回避・調査重視  
**好む情報**: 比較表・スペック・ランキング

#### 表示方法

**レイアウト**:
- **3候補を横並び比較表形式**で表示
- 全スペック・価格・装備を並べて一覧可能に
- スクロールなしで全候補を見渡せる設計

**情報要素**:
```yaml
表示項目（優先度順）:
  1. 詳細スペック比較表（エンジン性能、燃費、寸法、装備）
  2. 価格帯と維持費の3台比較
  3. 各車種の長所・短所を箇条書き
  4. 他車種との比較データ（除外された車種も表示）
  5. ランキング情報（販売台数、評価スコア）
  6. 「なぜ外した？」セクションを展開表示（デフォルトON）
```

**UI要素**:
- 「詳細な比較表を見る」ボタン（モーダル表示）
- 「他の候補も見る」リンク（除外車種一覧）
- 各項目に△○◎の3段階評価アイコン

**トーン**:
> 「3台を徹底比較しました。それぞれの長所・短所を明確にしています。除外した車種も含め、全ての選択肢を検討いただけます。」

---

### 2.2 Satisficer（十分型）

**特徴**: 基準を満たせば決定・比較数を抑える  
**好む情報**: おすすめパッケージ・要点まとめ

#### 表示方法

**レイアウト**:
- **1位のみ大きく表示、2位・3位は小さく参考表示**
- 重要な3～5ポイントのみを強調
- シンプルなカード形式

**情報要素**:
```yaml
表示項目（優先度順）:
  1. 「あなたに最適な1台」として1位を強調
  2. 選定理由を3点に絞って表示
  3. 必須条件（予算、乗車人数）の合致を明示
  4. 「この1台で十分な理由」セクション
  5. 2位・3位は「参考：他の選択肢」として控えめに
```

**UI要素**:
- 「この車に決める」大きなCTAボタン
- 「他の選択肢も見る」折りたたみセクション（デフォルトOFF）
- チェックマーク付き「必須条件クリア」バッジ

**トーン**:
> 「あなたの条件を満たす最適な1台が見つかりました。この車があなたのニーズを十分に満たします。」

---

### 2.3 Authority-driven（権威依存型）

**特徴**: 専門家・ブランド・評価を信頼  
**好む情報**: 受賞・専門レビュー・実績

#### 表示方法

**レイアウト**:
- **専門家評価・受賞歴を最上部に配置**
- 権威性を示すバッジやアイコンを目立たせる
- 実績データを数値で強調

**情報要素**:
```yaml
表示項目（優先度順）:
  1. 専門家の評価・推奨コメント
  2. 受賞歴・ランキング順位
  3. ブランドの信頼性・歴史
  4. 販売実績・シェア
  5. メディア掲載実績
  6. 技術的な先進性（特許、業界初）
  7. 長期的な信頼性データ（故障率など）
```

**UI要素**:
- 「専門家評価」セクション（星5つ評価など）
- 「受賞歴」バッジ（カーオブザイヤーなど）
- 「販売実績 No.1」などの権威性表示
- 「専門誌レビュー」リンク

**トーン**:
> 「この車は〇〇賞を受賞し、専門家からも高い評価を得ています。長年の実績と信頼性が証明されています。」

---

### 2.4 Delegator（委任型）

**特徴**: 他者に評価・決定を任せる  
**好む情報**: スタッフおすすめ・人気構成

#### 表示方法

**レイアウト**:
- **「スタッフおすすめ」「人気No.1」を前面に**
- 他の人の選択を強調
- 相談・サポートへの導線を明確に

**情報要素**:
```yaml
表示項目（優先度順）:
  1. 「あなたと同じ条件の方に人気」
     - 条件の明示: 「家族4人・予算300万円台・通勤利用」など
     - マッチ条件を具体的に列挙
  2. 「スタッフが厳選した3台」
  3. 他のユーザーの選択率（「70%の方が選択」）
     - 母数も表示: 「同じ条件の100名中70名が選択」
  4. よくある選択理由（他者の声）
     - 「同じ条件の方のコメント」として引用
  5. 推奨構成・オプション
     - 「この条件で人気のオプション」明記
  6. 「迷ったらこれ」明確な1台推し
```

**条件マッチングの詳細**:

以下の項目で「同じ条件」を判定し、明示的に表示:

| 条件項目 | 取得元 | 表示例 |
|---------|--------|--------|
| **家族構成** | プロファイル入力 | 「家族4人」「お子様2人」 |
| **予算帯** | プロファイル入力 | 「予算300-400万円」 |
| **主な用途** | Quick Questions q2 | 「週末のお出かけ重視」 |
| **価値観** | Quick Questions 全体 | 「安全・安心を重視」 |
| **DecisionStyle** | 意思決定スタイル | 「同じ委任型の方」 |

**表示例**:

> 「あなたと同じ条件の方に人気」
> 
> ✓ 家族4人（お子様2人）  
> ✓ 予算300-400万円  
> ✓ 週末のファミリーレジャー重視  
> ✓ 安全・安心を最優先
> 
> → この条件の方の **75%**（過去6ヶ月で120名中90名）がこの車を選択されています

**UI要素**:
- 「スタッフおすすめ」大きなバッジ
- 「人気構成で選ぶ」ボタン
- 「専門スタッフに相談する」目立つCTA
- 「この条件なら多くの方がこれを選択」メッセージ
- チャット/電話相談への導線

**トーン**:
> 「多くのお客様があなたと同じ条件でこの車を選ばれています。スタッフが自信を持っておすすめします。ご不明点があればいつでもご相談ください。」

---

### 2.5 Intuitive（直感型）

**特徴**: 感触・デザイン・体験重視  
**好む情報**: 試乗・ストーリー・ビジュアル

#### 表示方法

**レイアウト**:
- **大きな画像・動画を中心に**
- ビジュアル優先、テキスト最小限
- ストーリー性のある流れ

**情報要素**:
```yaml
表示項目（優先度順）:
  1. 大きな魅力的な車両画像（複数角度）
  2. 「この車との生活」ストーリー
  3. デザインの特徴（ビジュアル強調）
  4. 実際の乗り心地・体験の描写
  5. 所有する喜び・感情的価値
  6. カラーバリエーション表示
  7. 「試乗してみませんか？」への導線
```

**UI要素**:
- 大きな画像ギャラリー（スワイプ可能）
- 「試乗予約」目立つCTA
- 動画プレビュー（走行シーン、内装）
- カラーシミュレーター
- 「この車で叶う生活」ビジュアルストーリー

**トーン**:
> 「この車との暮らしを想像してみてください。洗練されたデザインと心地よい走りが、あなたの日常を特別なものにします。ぜひ試乗でその感覚を確かめてください。」

---

### 2.6 Impulsive（衝動型）

**特徴**: 即決・キャンペーン敏感  
**好む情報**: 限定・値引き・在庫

#### 表示方法

**レイアウト**:
- **緊急性・希少性を強調**
- 目立つ色使い（赤・オレンジ）
- 即決を促すメッセージ

**情報要素**:
```yaml
表示項目（優先度順）:
  1. 「今だけ」「残りわずか」限定情報
  2. 特別価格・キャンペーン
  3. 在庫状況（「この色は残り2台」）
  4. 即決特典
  5. 納期情報（「今なら〇月納車」）
  6. 簡潔な決定ポイント（3つまで）
```

**UI要素**:
- 「今すぐ予約」大きな赤色CTA
- カウントダウンタイマー（キャンペーン期限）
- 「在庫残りわずか」警告バッジ
- 「今月限定特典」目立つバナー
- ワンクリック見積もり・予約

**トーン**:
> 「今月限定の特別価格！この条件は今だけです。在庫も残りわずかとなっております。今すぐご予約いただくと〇〇特典付きです。」

---

## 3. 実装優先度

### Phase 1（必須）
- Maximizer: 比較表形式
- Satisficer: 1位強調表示
- その他: デフォルト表示（現状維持）

### Phase 2（推奨）
- Authority-driven: 専門家評価強調
- Intuitive: 画像優先レイアウト
- Impulsive: 緊急性強調

### Phase 3（オプション）
- Delegator: サポート導線強化（人数が少ないため優先度低）

---

## 4. 技術実装のポイント

### 4.1 条件分岐

```typescript
switch (decisionStyle) {
  case "Maximizer":
    return <MaximizerLayout recommendations={...} />;
  case "Satisficer":
    return <SatisficerLayout recommendations={...} />;
  case "Authority-driven":
    return <AuthorityLayout recommendations={...} />;
  case "Delegator":
    return <DelegatorLayout recommendations={...} />;
  case "Intuitive":
    return <IntuitiveLayout recommendations={...} />;
  case "Impulsive":
    return <ImpulsiveLayout recommendations={...} />;
  default:
    return <DefaultLayout recommendations={...} />;
}
```

### 4.2 共通コンポーネント + スタイル別プリセット

- 基本カードコンポーネントは共通
- `presentation` prop でレイアウト・情報密度を調整
- CSS/Tailwindクラスでスタイル切り替え

### 4.3 データ要件

各車種に以下のメタデータを追加（段階的に）:
- 専門家評価スコア
- 受賞歴
- 販売ランキング
- 人気度（選択率）
- 画像アセット（複数角度）

---

## 5. A/Bテスト指標

各スタイル別表示の効果測定:

| 指標 | 説明 |
|------|------|
| **滞在時間** | 推薦結果ページの閲覧時間 |
| **クリック率** | 詳細情報・CTAボタンのクリック率 |
| **意思決定速度** | 推薦から次アクションまでの時間 |
| **満足度** | 推薦結果への納得感（5段階評価） |
| **離脱率** | ページ離脱率 |

**期待値**:
- Satisficer: 意思決定速度↑（30%改善）
- Maximizer: 滞在時間↑、満足度↑（詳細情報提供により）
- Impulsive: クリック率↑、即決率↑（50%改善）

## 6. 参考: 既存実装との統合

現在の `StyleAwareRecommendSection` コンポーネントを拡張:

```typescript
  excluded={excluded}
  delegationLevel={delegationLevel}

  recommendations={recommendations}
  excluded={excluded}
  delegationLevel={delegationLevel}
/>
```

## 付録: スタイル別キーワード

| スタイル | キーワード | 避けるべき表現 |
|---------|-----------|---------------|
| Maximizer | 徹底比較、全データ、詳細分析 | シンプル、おまかせ |
| Satisficer | 十分、最適な1台、クリア | 選択肢多数、要検討 |
| Authority-driven | 専門家、実績、信頼 | 主観的、感覚的 |
| Delegator | おすすめ、人気、相談 | 自分で選ぶ、比較 |
| Intuitive | 感じる、体験、デザイン | スペック、数値 |
| Impulsive | 今すぐ、限定、残りわずか | じっくり、検討 |
